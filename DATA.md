# Data shipped with this repository

Everything in this folder is small, redistributable device or pose data that the code needs in
order to run. Video datasets are **not** included (see below).

## Device measurements (`data/`)

All device files are Agilent B1500A exports; the loader in `automatic_fall_detector.py`
(`load_conductance_values`) reads the `DataValue, <t>, <I>` rows and keeps positive currents.

| file | measurement | read bias | samples | used for |
|---|---|---|---|---|
| `HRS.csv` | high-resistance state, continuous read | 0.1 V | 8,362 valid | conductance distribution for device-aware encoding / weight quantisation |
| `LRS.csv` | low-resistance state, continuous read | 0.1 V | 2,223 valid | same as above |
| `EPSC.csv` | single 2 V / 1 ms pulse, 0.2 V read | 0.2 V | 1 ms window | — | excitatory post-synaptic current term |
| `LTP-1ms-阶梯付 [(1) ; 7_28_2026 7_59_16 PM].csv` | potentiation staircase | — | — | — | long-term plasticity term |
| `LTD-1ms-阶梯 [(1) ; 7_28_2026 7_53_06 PM].csv` | depression staircase | — | — | — | long-term plasticity term |
| `PPF-0.001-60-60.xls` | paired-pulse facilitation | — | — | — | short-term plasticity term |

`HRS.csv` and `LRS.csv` hold the **readout-current values** measured at a 0.1 V read voltage on
one device; the timestamps are set to zero because only the value distributions are used. They are
the sampling pools from which `image_to_crossbar_array` draws the per-pixel conductance of the
crossbar array (dark pixels from `HRS.csv`, bright pixels from `LRS.csv`), after the two arrays are
normalised by their joint maximum. The measured traces therefore carry the state-dependent readout
scatter that the device-aware encoding relies on. They are independent of the long-duration
retention trace used for the stability figure (10⁵ s at 0.01 V read, plotted separately in the
manuscript), which uses a different read level; because the HRS conduction is not ohmic, the
on/off ratio obtained from these 0.1 V readout values is lower than the 0.01 V retention figure.
Raw time-resolved traces are available on request.

## Trained weights (`models/`)

Four leave-one-subject-out checkpoints (seed 11, full device model) used by
`5.9new/crossbar+/CNN+SNN/s30_pose/scripts/repro_v1001_protocol.py`:

```
models/automatic_fall_event_detector_c1_s34_data1_loso_ts{1,2,3,4}_s11.pth
```

## Pose cache (`pose_cache/`)

8-D MediaPipe BlazePose features per frame, cached as `.npz` per video (392 files, 26.5 MB).
The checkpoints store an absolute `pose_cache_dir` from the original machine, so evaluation
must override it, otherwise every pose feature is silently zero and all videos are classified
as normal activity. Pass `pose_cache/` (this folder) as the cache directory, e.g.

```bash
python 5.9new/crossbar+/CNN+SNN/s30_pose/scripts/repro_v1001_protocol.py \
    --pose-cache-dir pose_cache
```

## DFT calculations (`dft/`)

Quantum ESPRESSO inputs, relaxed structures and plot-ready data behind Figure 3(a-e)
and Supplementary Note S5: ordered Zn0.5Ni0.25Cu0.25Fe2O4 cell (56 atoms), three
candidate oxygen vacancies (55 atoms) and the five-image CI-NEB oxygen migration path.
About 3 MB in total. `dft/README.md` documents the model, the settings and every number
quoted in the manuscript; `dft/03_data/data_validation.json` maps each quoted value to
the file it came from. Raw QE outputs (~340 MB) are not tracked (see below).

## Label tables (`data/`)

The dataset ships as `<root>/Subject <n>/{ADL,Fall}/<video>`, so labels come from the folder
names only. Two tables are generated by `tools/build_video_labels.py`:

| file | contents |
|---|---|
| `video_labels.csv` | one row per video (`video_name, relative_path, subject, category, label_id`; Fall = 1, ADL = 0). 160 rows for GMDCSA-24 v2.1 (79 falls / 81 activities of daily living), matching the 32/48/43/37 split used in the manuscript |
| `fall_video_frame_labels.csv` | frame-level labels for one demo video (`Subject 1/Fall/01.mp4`, 203 frames, label 1) in the format `automatic_fall_detector.py --labels-csv` expects for single-video training |

```bash
python tools/build_video_labels.py --root /path/to/GMDCSA24 --out data/video_labels.csv \
    --frames-video "Subject 1/Fall/01.mp4" --frames-out data/fall_video_frame_labels.csv
```
