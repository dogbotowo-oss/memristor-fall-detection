# v8 Final 批注回复

## 1. 这个阈值是怎么确定的

这里的“阈值”不是拍脑袋定的，而是先在验证集上做扫描，再结合事件分数的归一化结果来定。

逻辑是：

1. 先从窗口里提取 `fall_event_score`
2. 再把这个分数归一化
3. 只有当归一化后的动态突变足够强时，才让它明显进入 `fusion gate`

所以这个阈值本质上控制的是：

- 窗口里的动态变化够不够像“真正的跌倒瞬间”
- 低于阈值时，事件信号会被明显压弱
- 高于阈值时，事件信号才会更强地参与融合

它的作用不是直接判定“是不是跌倒”，而是先决定“这个窗口值不值得重点关注”。

## 2. 前几轮冻结 CNN/GRU 是什么意思

这里不是说整轮训练只做部分样本，而是说：

- CNN encoder、projection、GRU 仍然参与前向传播
- 但它们的参数先不更新
- 反向传播时，优先更新 SNN 分支和融合头

对应到代码里，就是把这些模块的参数临时设成 `requires_grad=False`。

这样做的目的有三个：

1. 先让新加的 SNN 时序分支稳定下来
2. 避免 CNN/GRU 和 SNN 一开始一起剧烈震荡
3. 等 SNN 学到比较合理的工作区间后，再解冻联合训练

所以它不是“只做前向、不做反向”，而是“整网都前向，只有部分参数参与更新”。

## 3. 我认可的方向

我这里认可的方向是：

- 不把所有 ADL 都当成同一种难样本
- 对低姿态、弯腰、受控下沉这类动作，按子类型细分 gate 抑制
- 让模型更像是在学“哪些 ADL 容易和 Fall 混淆”，而不是粗暴压制 ADL

这就是后续 v11 继续优化的基础。
